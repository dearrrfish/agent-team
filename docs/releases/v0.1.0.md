# agent-team v0.1.0

Release date: 2026-09-15

This is the first source/Nix release of `agent-team`, a portable workflow and
native-profile generator for role-based coding-agent teams.

## Highlights

- Use the same six semantic roles and workflow contract with Codex, Claude Code,
  or Antigravity CLI while keeping execution inside each client's native agent
  runtime.
- Scale from coordinator-only `solo` work to serialized `assisted` delegation or
  file-disjoint/worktree-isolated `team` execution with independent review.
- Persist requirements, plans, task dependencies, decisions, worker evidence,
  review cycles, verification, and completion state across agent sessions.
- Route roles through economy, balanced, or quality presets without embedding
  client-specific model names in portable role definitions.
- Preview every installation, refuse unmanaged or drifted content, and back up
  explicitly forced replacements.

## Installation

Run from a local source checkout:

```console
nix run . -- --version
```

Or install that checkout into a Nix profile:

```console
nix profile install /path/to/agent-team
agent-team --version
```

No canonical remote is configured for v0.1.0, so the release notes intentionally
do not advertise a remote flake URL.

## Verification

The core `nix flake check` gate builds the application, runs the Python unit
suite and Ruff, ShellChecks the release smoke script, validates the documentation
with Markdownlint, and exercises the installed binary through initialization,
validation, team-run creation, all-target render and apply, repeat-apply
idempotence, and doctor diagnostics.

The release has been built and run on `x86_64-linux`. All declared aarch64
derivations evaluate successfully without building.

## Known limitations

- There is no live cross-client orchestration; every client runs its own native
  subagents.
- Claude Code and Antigravity remain experimental until their model-backed role
  selection checks are complete.
- `aarch64-linux` lacks native runtime evidence.
- macOS packaging is deferred.
- Managed files that disappear from current output are reported as stale but are
  not automatically removed in schema v1.
- User-scope installation is global to the current user's native client paths.

## Upgrade notes

This is the initial release, so there is no prior configuration or state
migration. Configuration schema version 1 and install-state schema version 1
are strict; future incompatible changes will require an explicit migration path.
